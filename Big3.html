5. 실제 실행 시간 측정

import time
import statistics

def linear_sum(n):
    s = 0
    for i in range(n):
        s += i
    return s

linear_sum(1000)  # 워밍업: 측정 구간 밖
for n in [10000, 100000]:
    times = []
    for _ in range(5):
        start = time.perf_counter()
        result = linear_sum(n)
        elapsed = time.perf_counter() - start
        assert result == n * (n - 1) // 2
        times.append(elapsed)
    print(f"n={n}, 중앙값={statistics.median(times):.6f}초")

6. 선형 탐색과 이진 탐색의 조건

def linear_search(a, target):
    for i in range(len(a)):
        if a[i] == target:
            return i
    return -1

def binary_search(a, target):
    left, right = 0, len(a) - 1
    while left <= right:
        mid = (left + right) // 2
        if a[mid] == target:
            return mid
        if target < a[mid]:
            right = mid - 1
        else:
            left = mid + 1
    return -1

a = [2, 5, 8, 12, 16, 23, 38]
print(linear_search(a, 23))
print(binary_search(a, 23))

7. 알고리즘 전략: 탐욕과 동적계획법

def greedy_count(amount, coins):
    count = 0
    for coin in sorted(coins, reverse=True):
        count += amount // coin
        amount %= coin
    return count if amount == 0 else -1

def dp_count(amount, coins):
    dp = [float("inf")] * (amount + 1)
    dp[0] = 0
    for value in range(1, amount + 1):
        for coin in coins:
            if coin <= value:
                dp[value] = min(dp[value], dp[value - coin] + 1)
    return dp[amount] if dp[amount] != float("inf") else -1

coins = [1, 3, 4]  # 각 동전은 제한 없이 사용 가능
print("탐욕:", greedy_count(6, coins))
print("DP:", dp_count(6, coins))

양의 정수 동전으로 합계 6을 만들 때의 설명으로 옳은 것을 1개 고르시오.

def fast_guess(a, target):
    if a and a[0] == target:

def correct_search(a, target):
    for i, value in enumerate(a):

def sum_once(data):
    total = 0
    count = 0
    for x in data:
        total += x
        count += 1
    return total, count

def sum_twice(data):
    total = 0
    count = 0
    for x in data:
        total += x
        count += 1
    for x in data:
        total += x
        count += 1
    return total // 2, count

for n in [10, 100]:
    data = list(range(n))

10. 종합 선택: 정렬 준비 비용과 반복 탐색

from bisect import bisect_left

def linear_contains(a, target):
    for value in a:
        if value == target:
            return True
    return False

def binary_contains(ordered, target):
    i = bisect_left(ordered, target)
    return i < len(ordered) and ordered[i] == target

raw = [23, 2, 16, 5, 8, 12, 38]
targets = [23, 7, 12]
print("선형 반복:", [linear_contains(raw, t) for t in targets])
ordered = sorted(raw)  # 탐색을 반복하기 전에 한 번만 정렬
print("정렬 후 이진:", [binary_contains(ordered, t) for t in targets])

자료는 탐색 중 변경되지 않으며, 원래 인덱스가 아닌 존재 여부만 필요하다. n은 자료 수, q는 목표 수이다. 일반 비교 정렬의 최악 O(n log n)을 가정할 때 옳은 설명을 1개 고르시오.

정렬 후 이진: [True, False, True]

1. 입력 크기와 연산 횟수 · 정답 ①

  • ① 옳음 — 이 문제에서는 리스트 길이를 입력 크기로 정의한다.
  • ② 틀림 — 반환값과 관계없이 모든 원소를 처리하므로 total은 O(n)이다.
  • ③ 틀림 — 원소마다 한 번 더하므로 n이 두 배가 되면 덧셈 횟수도 두 배가 된다.
  • ④ 틀림 — 합계는 모두 0이지만 덧셈 횟수는 4, 8, 16회로 다르다.
  • ⑤ 틀림 — 연산 횟수만으로 특정 환경에서의 실행 초를 정확히 결정할 수 없다.

2. 빅오 표기법의 의미 · 정답 ④

  • ① 틀림 — 바깥 반복이 n번이 아니라 고정된 3번이다.
  • ② 틀림 — 바깥 반복은 고정된 3회이므로 대표 연산 횟수는 3n + 2이다.
  • ③ 틀림 — 반복문의 겹수만으로 복잡도를 결정하지 않는다.
  • ④ 옳음 — 3n + 2의 주된 증가 항은 n에 비례한다.
  • ⑤ 틀림 — 빅오는 정확한 실행 초를 나타내지 않는다.

3. O(1), O(log n), O(n)의 코드 연결 · 정답 ⑤

  • ① 틀림 — 반환값의 수치는 복잡도를 결정하지 않으며 첫 원소 접근은 O(1)이다.
  • ② 틀림 — n //= 2는 n을 절반으로 줄인다.
  • ③ 틀림 — 모든 원소를 방문하므로 O(n)이다.
  • ④ 틀림 — first는 인덱스 0의 원소만 읽으므로 원소 접근은 1회이다.
  • ⑤ 옳음 — n=16이면 16→8→4→2→1로 4회 반복한다.

4. O(n²)과 중첩 반복문 · 정답 ①

  • ① 옳음 — i의 n가지 경우마다 j가 n번 반복하므로 n×n회이다.
  • ② 틀림 — 16회에서 64회로 네 배 증가한다.
  • ③ 틀림 — 안쪽이 고정 3회이면 3n회이므로 선형 성장이다.
  • ④ 틀림 — i == j를 제외하는 조건이 없으므로 자기 자신과의 쌍도 센다.
  • ⑤ 틀림 — 대표 연산은 n²회이므로 입력이 두 배가 되면 네 배가 된다.

5. 실제 실행 시간 측정 · 정답 ③

  • ① 틀림 — 단일 실험만으로 점근적인 증가율을 확정할 수 없다. 코드 분석과 여러 규모의 실험을 함께 본다.
  • ② 틀림 — 해당 호출의 경과 시간은 종료 시각과 시작 시각의 차이로 구한다. 반환값 하나만으로는 알 수 없다.
  • ③ 옳음 — 실행 환경과 시스템의 실행 중단 등이 측정 시간에 영향을 줄 수 있다.
  • ④ 틀림 — 연산량의 비율과 실측 시간의 비율이 정확히 일치할 필요는 없다.
  • ⑤ 틀림 — 워밍업은 루프 전에, 출력은 측정 후에 실행된다.

6. 선형 탐색과 이진 탐색의 조건 · 정답 ④

  • ① 틀림 — 선형 탐색은 정렬 여부와 무관하게 사용할 수 있다.
  • ② 틀림 — 예제에서 선형 탐색은 6개, 이진 탐색은 가운데 원소 2개를 확인한다.
  • ③ 틀림 — 정렬 조건이 없으면 버린 구간에 정답이 있을 수 있다.
  • ④ 옳음 — 없는 목표를 찾으려면 n개를 모두 확인한다.
  • ⑤ 틀림 — 정렬된 리스트에서는 탐색 범위를 절반가량 줄이므로 최악 O(log n)이다.

7. 알고리즘 전략: 탐욕과 동적계획법 · 정답 ②

  • ① 틀림 — 큰 동전부터 고르는 이 구현은 4+1+1을 선택하여 동전 3개를 사용한다.
  • ② 옳음 — dp[value - coin]에 저장된 값을 이용하며 6은 3+3의 2개로 만들 수 있다.
  • ③ 틀림 — 오히려 최적해 2개보다 많은 3개를 사용한 반례이다.
  • ④ 틀림 — dp 배열을 통해 부분 문제의 결과를 재사용한다.
  • ⑤ 틀림 — 전략만으로 모든 문제의 복잡도가 같아지지 않는다. 가지치기 조건과 부분 문제 구조도 영향을 준다.

8. 정확성과 적용 조건을 함께 확인하기 · 정답 ④

  • ① 틀림 — 빠르더라도 정확하지 않으면 해당 문제의 해결 알고리즘으로 선택할 수 없다.
  • ② 틀림 — 8은 인덱스 2에 있지만 첫 원소만 검사하고 -1을 반환한다.
  • ③ 틀림 — 첫 원소 2만 확인한 뒤 -1을 반환하므로 인덱스 2의 목표를 놓친다.
  • ④ 옳음 — correct_search는 요구를 만족하며, 없는 값이나 뒤쪽 목표는 선형 시간이 필요하다.
  • ⑤ 틀림 — 일부 입력에서의 일치가 모든 입력에서의 동등성을 보장하지 않는다.

9. 효율성 비교와 실험 설계 · 정답 ①

  • ① 옳음 — 상수배를 생략하면 둘 다 선형 성장이지만 수행하는 덧셈 수는 다르다.
  • ② 틀림 — 빅오는 상수 계수와 세부 구현 비용의 차이를 없애 주지 않는다.
  • ③ 틀림 — 정답이 같아도 효율성은 다를 수 있다.
  • ④ 틀림 — 동일한 문제 조건과 입력으로 비교하여 불필요한 차이를 통제해야 한다.
  • ⑤ 틀림 — 단발성 실측만으로 점근적 증가율을 확정할 수 없다. 반복 측정과 연산 횟수 분석을 함께 해석해야 한다.

10. 종합 선택: 정렬 준비 비용과 반복 탐색 · 정답 ④

  • ① 틀림 — 초기 정렬 준비 비용을 빠뜨린 설명이다.
  • ② 틀림 — 한 번의 선형 탐색이 최악 O(n)이므로 q번 반복하는 비용은 O(qn)이다.
  • ③ 틀림 — 한 번만 찾을 때는 정렬 준비 비용 때문에 선형 탐색이 유리할 수 있다.
  • ④ 옳음 — 정렬을 한 번 수행하고 로그 시간 탐색을 q번 하는 비용을 더한다.
  • ⑤ 틀림 — 함수는 불리언을 반환한다. 원래 위치가 필요하면 별도 위치 정보를 보존해야 한다.
